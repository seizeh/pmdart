# ADR-0007: 커버리지 목표 대신 래칫(하한 고정)

- 상태: 채택 (2026-07)
- 관련: `.github/workflows/ci.yml`(커버리지 게이트), 이슈 #158,
  `pmdb/supabase/tests/*.sql`(pgTAP 16종)

## 맥락

이 코드베이스의 라인 커버리지는 17% 대다(도입 시점 12%). 낮은 이유는 게으름이 아니라 **구조** 다 —
DI 가 없어 리포지토리를 테스트에서 갈아끼울 수 없고, 1,000줄 넘는 화면이 8개다
([ADR-0008](0008-state-holders-without-framework.md), 이슈 #155·#156).

이 상태에서 "커버리지 80% 목표" 를 CI 에 적으면 **첫날부터 빨간불이고, 곧 게이트를 끈다.**
지키지 않는 기준은 없는 기준보다 나쁘다.

## 결정

**달성 가능한 현재값을 하한으로 고정하고, 커버리지가 오르는 만큼 하한을 따라 올린다(래칫).**

```yaml
- name: 커버리지 요약·게이트(≥17%)
  run: |
    awk -F'[:,]' '/^DA:/{t++; if($3>0) h++}
      END{pct=h*100/t; printf "라인 커버리지 %.1f%% (%d/%d)\n", pct, h, t;
          exit (pct>=17)?0:1}' coverage/lcov.info | tee -a "$GITHUB_STEP_SUMMARY"
```

보증하는 것은 **"떨어지지 않는다"** 이지 "충분하다" 가 아니다.

커버리지 수치로 잡히지 않는 부분은 **다른 층에서** 막는다.

| 대상 | 수단 |
|---|---|
| DB 불변식 | pgTAP 16종 — 자기초대 차단, 팔로우 얼굴 분리, 채팅 삭제 권한 등 |
| 스키마 드리프트 | 마이그레이션 리플레이([ADR-0005](0005-db-change-management.md)) |
| 웹 런타임 회귀 | `dart:io` 게이트([ADR-0006](0006-web-port-dart-io-gate.md)) |
| 포맷·정적 분석 | `dart format --set-exit-if-changed`, `flutter analyze` |

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| 목표치(80%) 명시 | 달성 불가 → 게이트를 끄게 된다. 방치된 기준은 신호가 아니라 잡음 |
| 게이트 없음 | 커버리지가 조용히 0 으로 수렴한다 |
| 변경분 커버리지(diff coverage) | 도구 도입 비용. 래칫으로 같은 효과의 8할을 얻는다 |

## 결과

- 낮은 숫자가 저장소에 그대로 드러난다. 감추지 않는 게 요점이다.
  상태 홀더 전환(#155)으로 12% → 17% 가 되었고 하한도 따라 올렸다
- 화면을 상태 홀더로 분해할 때마다(#155) 홀더 테스트가 붙어 커버리지가 오르고,
  그때 하한을 올린다 — 로드맵은 이슈 #158
- **한계:** 라인 커버리지는 품질 지표가 아니다. 이 게이트가 보장하는 건
  "테스트를 지우면 CI 가 막는다" 뿐이다
