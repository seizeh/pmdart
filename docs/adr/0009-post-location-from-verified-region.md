# ADR-0009: 게시글 위치는 작성 GPS 가 아니라 작성자의 인증 동네

- 상태: 채택 (2026-07)
- 관련: `pmdb/supabase/migrations/20260713*_create_post_region_gate*.sql`,
  `users.region_code`, `pmlegal`(위치기반서비스 이용약관)

## 맥락

하이퍼로컬 서비스라 게시글에 위치가 필요하다. 가장 쉬운 구현은 **작성 시점의 GPS 를
게시글에 저장**하는 것이다. 하지만 그러면

- 산책 메이트 글에 **집 좌표가 그대로 박힌다.** 반려동물 산책 글은 성격상 생활권과
  시간대가 같이 노출돼, 좌표 정밀도가 곧 신변 위험이 된다
- 목적(동네 매칭)에 필요한 해상도는 **행정동**인데 좌표는 그보다 훨씬 정밀하다 —
  개인정보 최소수집 원칙에 어긋난다

## 결정

**게시글에 작성 시점 GPS 를 저장하지 않는다.** 게시글의 위치는
`users.region_code`(지역 인증으로 확정된 행정동)에서 가져온다.

- 지도·피드 필터는 전부 인증 동네 기준
- 위치 인증은 **30일 주기 재인증**. 이 값은 `verify-post-photo` 의 `REVERIFY_DAYS(30)`,
  DB 의 지역 게이트 트리거, **`pmlegal` 의 위치기반서비스 이용약관** 세 곳이 같은 숫자여야 한다
- GPS 원본이 필요한 곳(사진 촬영지 검증)은 **검증에만 쓰고 결과(일치 여부·행정동코드)만
  남긴다** — `photo_verifications.shot_lat/lng` 는 검증 로그이지 게시글 위치가 아니다

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| 작성 GPS 저장 + 표시할 때만 뭉개기 | 원본이 DB 에 남는 한 유출·오용 위험이 남는다 |
| 좌표에 랜덤 오프셋 | 여러 글을 모으면 역산된다. "뭉갠 척" 이 제일 나쁘다 |

## 결과

- 이동 중 작성한 글도 **인증 동네** 기준으로 노출된다(의도한 동작)
- 재인증 주기를 바꾸려면 세 곳을 함께 고쳐야 한다 — 코드와 약관이 어긋나면
  **법적 고지 위반**이라 한쪽만 고치면 안 된다
- 업체 모드 글은 예외 — 개인 동네 인증이 아니라 **승인된 사업장 주소** 기준
  ([ADR-0010](0010-business-two-faces.md))

### 실제로 밟은 함정

동네 인증 게이트를 트리거로 넣었는데, `create_post_verified` 의 **버려진 오버로드**에는
게이트가 없어 우회 경로가 남아 있었다([ADR-0003](0003-definer-view-write-paths.md) 참고).
"정책을 한 곳에 넣었다" 와 "정책이 모든 경로에 걸린다" 는 다르다.
