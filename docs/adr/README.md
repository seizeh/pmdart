# 설계 결정 기록 (ADR)

이 프로젝트에서 **왜 그렇게 만들었는지**, 그리고 **그 선택의 대가로 무엇을 밟았는지** 를
남긴 문서다. 각 문서에는 검토한 대안과, 실제로 겪은 사고·오작동이 함께 들어 있다.

기능 목록보다 이쪽이 코드베이스를 더 정확히 설명한다.

| # | 결정 | 무엇을 밟았나 |
|---|---|---|
| [0001](0001-custom-phone-auth.md) | Supabase Auth 대신 전화 OTP 커스텀 인증 | 무상태 JWT 라 **정지시킨 사용자가 30일간 계속 접근**됐다 → `app.uid()` 에 상태 게이트 |
| [0002](0002-invariants-in-db.md) | 불변식은 Edge Function 이 아니라 DB 에서 강제 | 함수는 막고 있었지만 **PostgREST 직접 INSERT 로 자기초대 행이 실제로 생성**됐다 |
| [0003](0003-definer-view-write-paths.md) | DEFINER 객체에 쓰기 경로를 만들지 않는다 | 공개 anon 키만으로 **로그인 없이 임의 계정 관리자 승격**이 가능했다(실증 확인) |
| [0004](0004-rls-invisible-rows.md) | 비가시 행 쓰기는 DEFINER RPC 로 | 소프트 삭제가 42501. INVOKER RPC 서브쿼리는 **에러 없이 NULL** 을 돌려준다 |
| [0005](0005-db-change-management.md) | 스냅샷 복원 → 마이그레이션 리플레이 | 켜자마자 **알림 얼굴 필터가 재정의로 유실**된 게 잡혔다. `add column if not exists` 가 FK 를 삼킨다 |
| [0006](0006-web-port-dart-io-gate.md) | `dart:io` 직접 사용을 CI 로 금지 | 웹에서 **컴파일은 되는데 런타임에 흰 화면**. 빌드로는 안 잡힌다 |
| [0007](0007-coverage-ratchet.md) | 커버리지 목표 대신 래칫(하한 고정) | 12% 를 감추지 않는다. 지키지 않는 80% 보다 지키는 12% |
| [0008](0008-state-holders-without-framework.md) | 프레임워크 없이 `ChangeNotifier` 홀더 | 부채를 인정한 문서다 — **다시 만든다면 처음부터 DI 를 넣는다** |
| [0009](0009-post-location-from-verified-region.md) | 게시글 위치는 작성 GPS 가 아닌 인증 동네 | 산책 글에 집 좌표가 박히는 문제. 재인증 주기는 **약관과 같은 숫자**여야 한다 |
| [0010](0010-business-two-faces.md) | 업체는 `user_type` 이 아니라 1:1 분리 | 얼굴 분리는 한 번 만들면 끝이 아니라 **계속 지켜야 하는 불변식**이다 |

## 이 기록을 남기는 이유

같은 함정을 두 번 밟지 않기 위해서다. 대부분은 **증상과 원인이 멀다** —
소프트 삭제 실패의 원인은 권한 설정이 아니라 SELECT 정책이었고, 웹 흰 화면의 원인은
빌드가 아니라 런타임이었고, 알림이 잘못 나가는 원인은 알림 코드가 아니라
두 달 전 마이그레이션의 `create or replace` 였다.

그래서 각 문서는 **결정만이 아니라 그 결정이 어긋났을 때 어떤 증상으로 나타나는지**
를 같이 적는다.

## 형식

새 결정을 추가할 때는 다음 골격을 따른다.

```
# ADR-000N: 제목
- 상태: 채택 | 대체됨 (날짜)
- 관련: 파일·PR·이슈

## 맥락      — 무엇이 문제였나
## 결정      — 무엇으로 정했나
## 검토한 대안 — 왜 다른 것을 안 했나
## 결과      — 이 선택의 대가는 무엇인가
### 실제로 밟은 함정 — 증상 → 원인 → 조치
```

상세 구현 패턴은 별도 문서로 분리한다(예: 상태 홀더 패턴은
[`docs/architecture-state.md`](../architecture-state.md)).
